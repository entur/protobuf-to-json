# protobuf-to-json

Fast protobuf to JSON conversion (ProtoJSON format, like `JsonFormat`), with filtering by path (anonymize, prune),
max string length and max size, following the rules of json-log-filter's Jackson filters. See README.md.

## Repository layout

```
path/                 Path matching for anonymize and prune (JDK only, Java 11, Android)
api/                  ProtobufJsonWriter, builder options, FilterContext and size/truncation logic (JDK only, Java 11, Android);
                      the test-jar has ReferenceFilter, the reference implementation of the filters
transcode/            Full protobuf, Jackson 3: plan package and the transcoding writer; the test-jar has the shared writer tests
stream/               Full protobuf, Jackson 3, Java 24: the CodedOutputStream writer (ClassFile API, hidden class)
accessor/             Full protobuf, Jackson 3, Java 24: the accessor writer, with code generated per message type which reads
                      the fields with their accessors (ClassFile API, hidden classes linked with invokedynamic); see
                      accessor/README.md for how it works
lite/                 Protobuf lite, Jackson 2 (Java 11, Android); the test-jar has the generated lite test messages
utility/              JsonFormatComparison and the JsonFormat writer (Jackson 3)
test-support/         Generated full test messages, RandomMessages, BenchmarkPayloads, ProtobufJacksonTestMessages, and
                      PayloadFiles, which writes test messages as files for the lite modules (not published)
benchmarks/           JMH benchmarks, Java 25 (benchmark-full, benchmark-lite; not published), see benchmarks/README.md
support/protobuf/     Test .proto files: protobuf conformance test messages, curioswitch protobuf-jackson test messages
.github/              GitHub Actions: branch verification, CodeQL, Maven Central releases (entur/gha-maven-central), dependabot
```

Module dependencies: `path` → `api` → `transcode` → `stream`, `transcode` → `accessor`, `api` → `lite`, `api` → `utility`. Tests use
`test-support`, `utility`, and the test-jars of `api` and `transcode`. Lite tests and benchmarks must not have the full
protobuf runtime on their classpath (protobuf-java and protobuf-javalite clash): they get the test messages as files,
written during their build by `PayloadFiles`, which exec-maven-plugin runs with test-support as a plugin dependency.

## Build

```bash
# compile, test and package all modules (needs Java 25)
./mvnw verify

# a single module and what it depends on
./mvnw verify -pl transcode -am

# as the release workflow does: sources and javadoc jars, deployed to target/staging-deploy
./mvnw deploy -Ppublication

# benchmarks
java -jar benchmarks/benchmark-full/target/benchmarks.jar -prof gc
```

## Conventions

- 4 spaces indentation, Javadoc on public types and methods; javadoc is built (and checked) by every build
- `path`, `api` and `lite` must only use APIs available on Android 8 (API level 26), checked by animal-sniffer;
  no records, `List.of`, `String.repeat` and similar in their main code
- tests use JUnit and Google Truth
- the full protobuf writers must write the same as `JsonFormat` (see `AbstractJsonFormatConformanceTest` and
  `AbstractProtobufJacksonConformanceTest`), and the filtering writers the same as `ReferenceFilter` applied to the
  unfiltered output (see `AbstractFilteringProtobufJsonWriterTest`); shared abstract tests live in the `transcode`
  test-jar and are extended per writer
- path expressions are `$.a.b`, `$.a.*.b` and `$..b`; there is no slash notation
- max string length only applies to text and bytes, not to 64-bit integers, enum names, timestamps, durations, NaN and
  infinity (`writeUntruncated`); as the reference filter only sees JSON, the tests give it the locations of those values
  (`UntruncatedValues` in test-support, also written to the files for the lite tests)
- no binary files in the sources: test data is generated, i.e. by `PayloadFiles` during the build
- the unfiltered writers are the fast path: keep filtering logic in the filtering writers, `FilteredJsonValues` and `FilterContext`
- the code generated by the accessor writer only reads fields and calls the methods of `AccessorJsonValues`, through
  `OutOfLineJsonValues`, whose methods are too large for the JIT to inline: inlining the writing of values into the code of
  every message type makes the compiled code so large that the JIT inlines less and optimizes worse (30% slower)
- `MessageWritersTest` checks that a writer is generated (not transcoded) for every test message type; generation
  failures fall back to transcoding silently
- the full writers write strings with `JsonValues.writeString`, which copies short strings to a (per thread) `char[]`:
  Jackson 3 writes short `String`s one `charAt` at a time, which is up to a third slower
